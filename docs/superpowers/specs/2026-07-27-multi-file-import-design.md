# 多文件数据导入设计

## 目标

“数据导入”页和“班级详情”页的本地文件上传入口均支持一次选择多个 Excel 文件。每个文件独立导入和记录结果；单个文件失败不阻断其他文件；整批文件处理完成后只运行一次班级分析。

## 范围

- 支持 `.xlsx` 和 `.xls` 文件多选。
- 保留现有服务器文件夹导入功能，不改变其使用方式。
- 不改变现有导入器、数据库表或文件类型识别规则。
- 保持单文件调用 `/api/import/upload` 的响应兼容性。

## 接口与处理流程

`POST /api/import/upload` 继续使用 multipart 字段 `file`，后端通过 `request.files.getlist('file')` 取得一个或多个文件。

处理顺序如下：

1. 校验当前活动班级与表单中的目标班级一致。
2. 过滤空文件名，并校验至少选择了一个文件。
3. 在开始导入前校验所有文件的扩展名；不支持的文件作为明确错误返回。
4. 对整批文件预检文件名中的班级信息。若存在冲突且尚未确认，返回 HTTP 409，并列出所有冲突文件；此时不保存、不导入任何文件。
5. 确认后按用户选择顺序逐个保存和调用现有 `import_data()`。
6. 捕获单个文件的异常并记录为该文件失败，然后继续处理后续文件。
7. 若至少一个文件成功，整批处理结束后调用一次 `run_all_analysis()`。

单文件请求继续返回现有的单文件结果结构。多文件请求返回批量结构：

```json
{
  "success": false,
  "partial_success": true,
  "total_files": 3,
  "imported_files": 2,
  "failed_files": 1,
  "total_imported_rows": 120,
  "results": [
    {"filename": "a.xlsx", "success": true, "imported_count": 60},
    {"filename": "b.xlsx", "success": false, "message": "无法识别文件类型"},
    {"filename": "c.xlsx", "success": true, "imported_count": 60}
  ]
}
```

批量响应的 `success` 仅在全部文件成功时为 `true`；成功和失败并存时 `partial_success` 为 `true`。

## 页面交互

两个上传控件都增加 `multiple` 属性，仍限制可选扩展名为 `.xlsx,.xls`。

- 未选择文件时显示原有提示。
- 选择一个文件时显示文件名。
- 选择多个文件时显示“已选择 N 个文件”。
- 提交后禁用上传按钮，显示上传和导入中的状态，避免重复提交。
- 班级冲突响应列出冲突文件；用户确认后使用同一批文件重新提交并携带 `confirm_class_mismatch=true`。
- 完成后显示总数、成功数、失败数、导入行数，以及逐文件成功或错误信息。
- 导入历史在批次完成后刷新一次。
- 请求结束后恢复上传按钮；网络或服务端错误也必须恢复按钮并显示安全转义后的消息。

## 错误与一致性

- 班级上下文错误和整批班级名称冲突在任何文件导入前返回，避免半批次提交后重试。
- 文件格式、解析、重复导入等文件级错误只影响对应文件。
- 批量导入不是跨文件数据库事务；已经成功导入的文件不会因其他文件失败而回滚，这与现有文件夹导入语义一致。
- 自动分析失败不改变文件导入结果，在响应中通过 `analysis_warning` 提示。
- 所有展示到页面的文件名和错误消息都经过 HTML 转义。

## 测试

后端测试覆盖：

- 多个文件按选择顺序传给导入逻辑，并汇总结果。
- 一个文件失败时后续文件继续导入，响应标记部分成功。
- 多文件班级冲突预检不产生任何导入；确认后可继续。
- 多文件成功后只运行一次分析。
- 单文件请求保持既有响应和行为。
- 空选择和不支持格式返回明确错误。

页面模板测试覆盖：

- 两个文件输入框均含 `multiple`。
- 两处脚本都能显示选择数量、提交整批文件、展示汇总和逐文件结果。
- 批量导入期间按钮禁用，请求完成后恢复。

## 验收标准

教师可在任一上传入口一次选择多个 Excel 文件，只提交一次；系统逐文件给出可追溯结果，部分失败不会阻断其他文件，班级分析每批最多执行一次，原有单文件上传仍可正常使用。
