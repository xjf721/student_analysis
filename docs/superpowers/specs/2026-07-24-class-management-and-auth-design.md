# 班级管理、数据隔离与登录模块设计

## 1. 背景与目标

系统现有数据展示以全量学生为默认范围。随着课程包含两个班级，首页、学生画像、知识点分析、风险预警和导入记录不能再混合展示。

本次改造目标如下：

- 增加班级管理功能，并支持班级启用、归档和恢复。
- 登录后选择一个全局当前班级，所有普通业务页面仅展示该班数据。
- 上传数据时显式指定班级，导入、分析和展示全过程保持同一班级作用域。
- 增加单一管理员登录模块，未认证用户不能使用系统。
- 增加独立班级对比页面，在用户明确操作时比较多个班级。
- 不保留现有数据库中的业务数据，升级后通过原始 Excel 文件重新导入。

## 2. 范围

### 2.1 本期包含

- 单一管理员登录、退出、会话管理和登录限流。
- 全局当前班级选择与切换。
- 班级新建、编辑、归档、恢复和空班级删除。
- 班级详情、班级数据概览、班级内上传及重新分析。
- 首页、学生画像、知识点分析、风险预警和导入记录的班级隔离。
- 文件名班级信息与用户选择班级的冲突校验。
- 班级对比页面。
- 带显式确认参数的数据库重建命令。
- 覆盖认证、隔离、导入和对比口径的自动化测试。

### 2.2 本期不包含

- 多用户管理。
- 教师与班级的权限分配。
- 学生跨班或跨学期的选课关系模型。
- 历史数据库业务数据迁移。
- 普通页面的全年级或全部班级混合视图。

## 3. 核心设计决策

采用“服务端登录会话 + 全局当前班级 + 后端强制过滤”的方案。

```text
登录
  -> 选择当前班级
  -> Session 保存 active_class_id
  -> 页面和 API 获取统一班级上下文
  -> Repository 和 Analyzer 按 class_id 查询
  -> 返回单班数据
```

班级 ID 不能仅依赖前端参数。普通业务接口必须从统一的服务端班级上下文取得当前班级，并在数据访问层实施过滤。只有独立的班级对比接口允许显式读取多个班级。

## 4. 数据模型

### 4.1 班级

沿用 `ClassInfo`，补充以下能力：

- 班级名称、任课教师和学期。
- 状态：`active` 或 `archived`。
- 可选备注。
- 创建时间和更新时间。

活动班级出现在顶部快速切换列表中。归档班级保留历史数据，可在班级管理页查看和恢复，但默认不出现在快速切换列表中。

### 4.2 学生及分析数据

- `Student.class_id` 决定学生所属班级。
- 行为、实践、作业明细、知识掌握和预警记录通过 `student_id` 间接归属班级。
- 班级级知识点汇总继续直接保存 `class_id`。
- 当前课程场景下学号仍保持全局唯一，不引入选课关系表。

### 4.3 导入记录

`ImportRecord` 增加：

- `class_id`：目标班级。
- `file_hash`：上传文件的 SHA-256 摘要。
- `uploaded_by`：本期固定记录管理员用户名。

重复导入按“班级 ID + 文件摘要”判断。两个班级可以上传同名或内容相同的文件，互不覆盖。文件名不再作为跨班级的唯一去重依据。

## 5. 认证与安全

### 5.1 管理员凭据

- 用户名从 `ADMIN_USERNAME` 环境变量读取。
- 密码使用 Werkzeug 兼容哈希，存放在 `ADMIN_PASSWORD_HASH` 环境变量中。
- 项目提供生成密码哈希的命令或脚本说明。
- 代码和示例配置中不提供可直接登录的默认密码。
- 缺少管理员凭据时，业务页面不可访问，并显示明确的部署配置提示。

### 5.2 会话

- 登录成功后重新生成登录会话状态。
- Session 保存认证状态、管理员用户名和 `active_class_id`。
- 退出时清除全部会话数据。
- Cookie 使用 `HttpOnly` 和 `SameSite=Lax`；生产 HTTPS 环境启用 `Secure`。
- `SECRET_KEY` 在生产环境必须通过环境变量配置。

### 5.3 请求保护

- 除登录页和静态资源外，所有页面和 API 默认要求认证。
- 登录失败统一返回“用户名或密码错误”。
- 连续登录失败触发短时限流。
- 登录、班级增删改、归档、恢复、上传和重新分析等写操作启用 CSRF 防护。
- 学生详情接口必须同时校验学生 ID 和当前班级，禁止通过修改 URL 读取其他班级学生。

## 6. 全局当前班级

### 6.1 选择规则

- 登录后若 Session 没有有效的 `active_class_id`，进入班级选择页。
- 用户选择班级后，将其 ID 保存到 Session，并进入该班首页。
- 顶部导航持续显示当前班级，并支持快速切换活动班级。
- 切换后，首页、学生、知识点、预警和导入记录同步使用新班级。
- 系统绝不以“全部班级”作为普通页面的默认兜底范围。

### 6.2 失效处理

- 当前班级不存在、被删除或不可用时，清除 `active_class_id` 并返回班级选择页。
- 归档当前班级后，立即退出该班级上下文。
- 没有数据的班级展示空状态与上传入口，不展示其他班级数据。

## 7. 班级管理

班级管理页以卡片或表格展示：

- 班级名称、学期、教师和状态。
- 学生人数。
- 已导入文件数。
- 最近一次导入或数据更新时间。

支持以下操作：

- 新建班级。
- 编辑班级名称、教师、学期和备注。
- 进入班级并设为当前班级。
- 归档活动班级。
- 恢复归档班级。
- 删除没有学生、分析数据及导入记录的空班级。

有业务数据的班级不允许直接删除。删除空班级、归档班级等操作需要二次确认。

班级详情页包含：

- 数据概览。
- 最近导入记录。
- 上传数据入口。
- “重新分析本班”操作。

## 8. 数据上传与分析流程

### 8.1 班级归属

- 从班级详情页上传时，目标班级被锁定为该班。
- 从通用导入页上传时，默认使用当前班级，但允许用户改选活动班级。
- 后端必须要求并校验目标 `class_id`，不能继续依赖文件名自动创建班级。
- 文件名解析出的班级信息只用于校验提示，不决定数据归属。

### 8.2 文件名冲突确认

若文件名识别出的班级与用户选择班级不一致：

1. 首次请求返回结构化冲突信息，不写入数据库。
2. 页面明确展示“识别班级”和“目标班级”。
3. 用户二次确认后携带一次性确认标记重新提交。
4. 后端再次校验目标班级后才执行导入。

### 8.3 事务与分析

- 每个文件导入使用独立事务。
- 单个文件失败时回滚该文件产生的变更，不影响其他文件或班级。
- 导入成功后只运行目标班级的行为、实践、知识和预警分析。
- “重新分析本班”也必须把当前 `class_id` 传给所有分析器。
- 分析结果返回每个分析器的成功、失败及错误信息。

## 9. 单班展示

以下页面和对应 API 必须使用当前班级：

- Dashboard 首页。
- 学生列表、搜索、详情和全览。
- 知识点排行、热力图和学生掌握情况。
- 风险预警统计、排行和明细。
- 数据导入记录。

页面固定显示当前班级标签。Repository 和 Analyzer 的班级参数对普通页面不得省略；调用方必须显式提供当前班级 ID，防止无意执行全量查询。

## 10. 班级对比

班级对比是唯一允许同时读取多个班级的业务页面。用户必须明确选择至少两个班级。

首版对比指标包括：

- 学生人数。
- 平均到课率或行为综合指标。
- 平均实践成绩。
- 平均知识掌握率。
- 预警学生数量与占比。

对比接口按班级分别聚合，不返回混合学生明细。每项指标必须复用或遵循单班页面的同一计算口径，确保对比值与各班首页一致。

## 11. 数据库重建

现有业务数据无需保留。项目提供受控的数据库重建命令：

- 未提供显式确认参数时只输出说明并拒绝执行。
- 提供确认参数后删除旧业务表，并根据当前模型重建完整结构。
- 重建不会在应用启动时自动执行。
- 日常启动仍执行非破坏性的缺列兼容检查。

推荐上线流程：

1. 停止旧应用。
2. 执行带确认参数的数据库重建命令。
3. 配置管理员用户名、密码哈希和生产 `SECRET_KEY`。
4. 启动应用并登录。
5. 创建两个班级。
6. 分别进入班级详情页上传对应 Excel。
7. 检查两个班级的单班页面及班级对比页面。

## 12. 错误处理

- 未登录：页面重定向到登录页，API 返回 401 JSON。
- 未选择班级：页面进入班级选择页，依赖班级的 API 返回明确的 409 JSON。
- 班级不存在或已归档：清理失效上下文并提示重新选择。
- 上传缺少班级：返回 400，不保存文件记录。
- 文件班级冲突：返回可供二次确认的业务响应，不开始导入。
- 跨班访问学生：返回 404 或统一的不可访问响应，不透露学生是否存在。
- 班级存在数据时请求删除：返回 409，并引导使用归档。
- 单文件导入失败：回滚该文件事务，并在导入记录中保存可读错误信息。

## 13. 测试与验收

### 13.1 认证测试

- 正确凭据登录成功。
- 错误用户名或密码登录失败且提示一致。
- 未登录页面跳转与 API 401 响应正确。
- 退出后原 Session 不再有效。
- CSRF 缺失或错误时写操作被拒绝。
- 连续失败触发限流。

### 13.2 班级管理测试

- 新建、编辑、归档和恢复班级。
- 空班级可以二次确认删除。
- 有数据班级不能删除。
- 归档当前班级后当前上下文被清除。

### 13.3 数据隔离测试

- 切换当前班级后，各页面和 API 只返回目标班级数据。
- 学生搜索只搜索当前班级。
- 手工修改学生 ID 或请求参数不能访问其他班级数据。
- 空班级不会回退到全量数据。
- 普通 Repository 和 Analyzer 调用不会因省略班级参数而执行全量查询。

### 13.4 导入测试

- 班级详情上传自动锁定目标班级。
- 通用导入页可以选择活动班级。
- 缺少班级时拒绝导入。
- 文件名识别班级冲突时，未经确认不得写入。
- 两个班级上传同名文件不会互相覆盖或误判重复。
- 导入成功后只分析目标班级。
- 单文件失败不影响其他文件和班级。

### 13.5 对比与端到端验收

- 对比指标与两个班级各自页面的统计口径一致。
- 对比接口不返回混合学生明细。
- 数据库重建命令缺少确认参数时拒绝执行。
- 使用两个测试班分别导入一套样例 Excel，检查首页、学生、知识、预警、导入记录和班级对比均不存在非预期混合数据。

## 14. 成功标准

- 未登录用户无法访问任何业务数据。
- 普通页面任一时刻只展示一个明确班级的数据。
- 上传、导入、分析和展示使用同一个目标班级。
- 同名文件和相似学生数据不会导致跨班覆盖。
- 班级对比只能通过独立入口发生，且计算口径与单班页面一致。
- 数据库可受控重建，并能通过重新上传 Excel 完成两个班级的数据初始化。
