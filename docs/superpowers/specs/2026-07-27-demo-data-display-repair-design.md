# 演示版数据展示修复设计

## 目标

快速恢复当前演示所需的四项能力：

1. 班级雷达画像能够根据当前班级的学习行为数据正常显示。
2. 学生画像能够显示已导入的雨课堂学习行为指标。
3. 数据导入页恢复“清空当前班级数据”功能。
4. 浏览器记住上次选择的班级，并在下次登录后自动恢复。

同时将项目规则文件 `AGENT.md` 重命名为通用名称 `AGENTS.md`，并在文件顶部明确写入：

> 本项目现阶段只做演示验证，追求快速验证功能效果，不必引入过多规范流程。

## 已确认事实

- 最新雨课堂学习过程文件可以被 `RainClassImporter` 正确解析，共识别 37 名学生及到课率、课件观看率、视频完成率、作答率和得分率。
- 2026-07-27 的运行日志显示 `student_behavior` 已插入或更新行为记录。
- `/api/radar` 已针对当前班级执行行为聚合并返回 HTTP 200。
- 网页端清空接口和按钮此前被测试明确要求移除，并非偶发消失。
- 当前班级只保存在 Flask 临时 Session 中，浏览器会话或服务变化后可能丢失。

## 方案

### 雷达图和行为数据

把两项现象作为同一条端到端链路修复：

- 雷达 API 同时返回当前班级学生数和行为记录数。
- 当前班级有行为记录时，返回五维雷达指标及数值。
- 有学生但没有行为记录时，页面显示“当前班级尚未导入学习行为数据”，不再出现无解释的空白图。
- 前端在初始化图表前检查 ECharts 是否加载；演示环境优先使用项目内可用的静态资源或明确的加载失败提示，避免静默空白。
- 学生详情继续从 `StudentBehavior` 展示同一组字段，缺失时显示明确空状态。

### 清空当前班级

在数据导入页恢复清空入口，但范围限定为当前活动班级：

- 保留 `ClassInfo` 班级记录。
- 删除当前班级学生关联的预警、作业关卡、作业明细、知识掌握、行为、实践和学生记录。
- 删除当前班级的知识点汇总和导入记录。
- 不影响其他班级。
- 页面确认框明确显示当前班级名称；成功后刷新导入记录和当前页面状态。

### 记住上次班级

采用浏览器本地记忆，不扩展用户偏好表：

- 每次成功选择班级后，把班级 ID 写入 `localStorage`。
- 登录后进入班级管理页；若服务端没有活动班级且本地保存的班级仍为活动状态，则自动调用现有班级选择接口并进入首页。
- 若班级不存在、已归档或不可用，则清除本地记录并停留在班级管理页。
- 后端仍以 Session 中的 `active_class_id` 为数据隔离依据，本地存储只用于恢复选择。

## 测试与验收

只增加本次演示需要的回归覆盖：

- 有学生和行为数据时，班级雷达 API 返回行为数量及五维数据。
- 有学生但没有行为数据时，页面显示明确空状态。
- 清空当前班级后，该班业务数据和导入记录为空，班级本身及其他班级数据保留。
- 选择班级会写入本地记忆，班级管理页能恢复有效班级并清理失效班级。
- Git 将 `AGENT.md` 到 `AGENTS.md` 识别为重命名，原有规则内容完整保留。

## 范围限制

- 不新增数据库偏好表。
- 不引入角色权限、审计审批、软删除或恢复站。
- 不重构无关导入器和页面。
- 不清理或改写现有业务数据，只提供用户主动触发的当前班级清空操作。
