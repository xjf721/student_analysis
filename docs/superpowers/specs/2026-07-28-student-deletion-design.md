# 单个学生删除功能设计

## 目标

教师可以在当前班级的学生列表中手动删除测试学生。删除会同时清理该学生的全部学习过程和分析数据，不影响同班或其他班级的学生。

删除不会建立忽略名单。后续重新导入包含同一学号的 Excel 时，系统允许重新创建该学生及其数据。

## 用户交互

- 在 `/students` 学生列表每行的“操作”列增加红色“删除”按钮。
- 点击后显示二次确认，确认文案包含学生姓名和学号，并说明其全部学习与分析数据将被删除。
- 用户取消时不发送请求。
- 删除成功后重新加载当前搜索结果，并显示成功提示。
- 删除失败时保留当前列表，并显示服务端返回的明确错误信息。

## API 设计

新增已登录且要求已选择班级的接口：

```text
DELETE /api/student/<student_id>
```

处理规则：

1. 从会话中取得当前班级 ID。
2. 仅查找同时匹配 `student_id` 和当前班级 ID 的学生。
3. 匹配成功时调用仓储层的原子删除方法。
4. 成功返回 HTTP 200，JSON 包含 `message` 和被删除学生的 `id`、`student_no`、`name`。
5. 学生不存在或属于其他班级时统一返回 HTTP 404，避免泄露其他班级的数据。
6. 数据库删除失败时回滚整个事务，记录错误日志，并返回 HTTP 500。

## 数据删除设计

`StudentRepository` 提供带 `student_id` 和 `class_id` 的删除方法。删除在同一个数据库事务中执行，不依赖 ORM 关系级联或数据库 `ON DELETE CASCADE`。

显式删除顺序：

1. `student_assignment_challenge`
2. `student_assignment_detail`
3. `student_behavior`
4. `student_practice`
5. `student_knowledge_mastery`
6. `warning_record`
7. `student`

先删除关卡明细是因为其同时引用作业明细和学生。所有批量删除使用同一个 session，只在全部成功后提交一次；任一操作异常时回滚。

`import_record` 和班级级知识点汇总不按学生关联，本功能不删除这两类记录。

## 安全与一致性

- 路由继续使用现有登录保护和 `require_active_class`。
- 班级 ID 只来自服务端会话，不接受查询参数或请求体覆盖。
- 现有全局 AJAX 配置会向 `DELETE` 请求附加 CSRF token。
- 不提供批量删除，降低误操作风险。
- 不修改导入器逻辑，因此同学号后续可重新导入。

## 测试范围

- 完整关联数据的学生删除后，七类学生级记录均不再存在。
- 同班其他学生和其他班级学生的数据保持不变。
- 当前班级不能删除其他班级的学生。
- 不存在的学生和重复删除返回 404。
- 学生列表包含删除按钮、带姓名和学号的确认文案，以及成功和失败处理。
- 删除后再运行现有导入逻辑时，同学号仍可被创建。

## 非目标

- 不实现软删除、恢复站或操作审计。
- 不实现学号忽略名单。
- 不实现批量删除。
- 不修改数据库外键约束或引入迁移框架。
